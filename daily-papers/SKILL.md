# 每日论文推荐

这是面向用户的一句话入口。对用户来说，正常只需要说一次：

- `今日论文推荐`
- `过去3天论文推荐`
- `过去一周论文推荐`

## 执行原则

1. 先识别时间范围：
   - `今日论文推荐`、`每日推荐`、`今日论文` -> 当天
   - `过去3天论文推荐`、`最近3天论文` -> 3 天
   - `过去一周论文推荐`、`看看这周有啥论文` -> 7 天
2. 自动调用 `/daily-papers-fetch`。
3. 第 1 步完成后，自动调用 `/daily-papers-review`。
4. **不自动调用笔记生成**。review 完成后向用户输出：`想精读哪篇？回复「精读 1,3,5」`
5. 用户回复 `精读 1,3,5` 时，自动调用 `/daily-papers-notes` 并传入索引参数。

## 重要约束

- 不要先要求用户手动跑 `跑一下论文抓取 / 点评 / 笔记`。
- 但 `精读 1,3,5` 是正常用户交互，应自动响应。
- 如果用户明确只想跑其中一步，再交给对应 skill。

## 推荐配额保障

每次推荐列表自动确保包含下列方向的论文（若候选池中有相关论文）：
- **GPU Inference / Serving** (1篇+)：LLM 推理优化、KV cache、speculative decoding、量化等
- **Agent Architecture & Design** (1篇+)：多智能体系统、工具使用、推理框架、agent 训练/评估等

这两个方向有独立的主题聚类和评分关键词，评分不足时通过配额兜底替换机制保障至少各有一篇。

## 自动化

- 本 skill 是”一步跑完整流水线”的入口，但只跑到 review（轻笔记）为止。
- 精读需要用户选择后再触发 notes 步骤。
- 如果用户想定时 cron 抓取，只 cron fetch 这一步即可。
